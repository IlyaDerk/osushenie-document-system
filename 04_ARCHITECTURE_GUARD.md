# Ограничение на изменение архитектуры

## Обязательное правило

Не изменять утверждённую архитектуру, структуру данных, имена листов, имена заголовков, ключи сущностей и существующие модули без отдельного явного согласования с владельцем проекта.

## Запрещено без согласования

- переименовывать листы;
- переименовывать или удалять заголовки;
- менять строки заголовков и начала данных;
- менять ключ `ID объекта + ID типа документа`;
- менять формат `ID документа`;
- вводить сущность договора или `ID договора`;
- менять источник истины для данных объекта;
- менять набор редактируемых полей карточки;
- менять `SystemCore.gs`, `Code.gs` или `OperatorSidebar.html`;
- заменять массовую обработку всех объектов обработкой выделенной строки;
- менять правило учёта архивных и удалённых строк;
- автоматически исправлять или удалять дубли;
- подключать новые API, базы или сторонние сервисы;
- перестраивать проект по собственной инициативе.

## Если изменение кажется необходимым

1. Не применять его.
2. Описать проблему.
3. Объяснить, почему текущая архитектура мешает.
4. Предложить минимальное изменение.
5. Перечислить затрагиваемые файлы, листы, поля и тесты.
6. Дождаться явного согласования.

Допускаются внутренние служебные функции нового файла, если они не меняют внешний контракт системы.
