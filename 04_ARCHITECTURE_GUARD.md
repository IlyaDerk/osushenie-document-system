# Ограничение на изменение архитектуры

## Обязательное правило

Не изменять утверждённую архитектуру, структуру данных, имена листов, имена заголовков, ключи сущностей и существующие модули без отдельного явного согласования с владельцем проекта.

## Запрещено без согласования

- переименовывать листы;
- переименовывать или удалять заголовки;
- менять строки заголовков и начала данных;
- менять ключ `ID объекта + ID типа документа`;
- менять формат `ID документа`;
- вводить сущность договора или `ID договора`;
- менять источник истины для данных объекта;
- менять набор редактируемых полей карточки;
- менять `SystemCore.gs`, `Code.gs` или `OperatorSidebar.html`;
- заменять массовую обработку всех объектов обработкой выделенной строки;
- менять правило учёта архивных и удалённых строк;
- автоматически исправлять или удалять дубли;
- подключать новые API, базы или сторонние сервисы;
- перестраивать проект по собственной инициативе.

## Если изменение кажется необходимым

1. Не применять его.
2. Описать проблему.
3. Объяснить, почему текущая архитектура мешает.
4. Предложить минимальное изменение.
5. Перечислить затрагиваемые файлы, листы, поля и тесты.
6. Дождаться явного согласования.

Допускаются внутренние служебные функции нового файла, если они не меняют внешний контракт системы.

## Согласованный пакет синхронизации объектов

В рамках отдельно поставленного владельцем задания разрешены только минимальные
изменения `SystemCore.gs`: системные значения операции синхронизации, совместимые
генераторы читаемых ID, общий безопасный HTML-диалог и необязательная функция
`setupSystemDictionaryGuards`. Новые заголовки, листы и сущности не вводятся.

`SyncObjectData.gs` является отдельным рабочим модулем. Источник истины — только лист
`Объекты`; получатель — только активные строки `Документы объектов`. Модуль не меняет
карточку операциониста, `onOpen`, ключ создания, формат ID документа, структуру листов
или пользовательские варианты справочника. Он проверяет только `OBJECTS`, `DOCUMENTS`,
`CARD_DICTIONARY`, `OPERATION_HISTORY` и `CHANGE_HISTORY` через
`assertSystemSheetsStructure_(sheetKeys)`.

Document Properties хранит только зарезервированный дневной максимум номера операции,
чтобы удаление строк истории не приводило к повтору ID. Данные предметной области и
системные заголовки там не хранятся; `SystemCore.gs` остаётся единственным источником
системной конфигурации.

## Ручная архивация «История изменений»

- Архивация выполняется только вручную функцией `archiveChangeHistoryByDate`; автоматические триггеры и правило 90 дней не вводятся.
- Настройка папки хранится только в Script Properties по ключу `CHANGE_HISTORY_ARCHIVE_FOLDER_ID` и задаётся функцией `setupChangeHistoryArchiveFolder`.
- Архивируется только лист «История изменений» во внешние Spreadsheet-файлы по месяцам; «История операций» остаётся в рабочем файле и получает одну строку о запуске архивации.
- Рабочие строки удаляются физически только после пакетной записи в архив и повторной проверки наличия всех переданных «ID изменения».
