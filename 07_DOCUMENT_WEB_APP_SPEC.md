# Web-приложение создания документов

## 1. Назначение и границы

Web App — мобильный интерфейс для создания новой строки в листе
«Документы объектов». Он не редактирует и не удаляет существующие строки.
Карточка операциониста и массовое создание документов остаются отдельными модулями.

## 2. Модули

- `DocumentWebApp.gs` — `doGet()`, чтение справочников, предпросмотр и создание под общей блокировкой.
- `WebAppAuth.gs` — серверная проверка логина/пароля и шестичасовая сессия Script Cache.
- `DocumentWebApp.html` — мобильные экраны входа и создания. Токен хранится в `sessionStorage`.
- `SystemCore.gs` — единый контракт листа, заголовков, значений и блокировки.

## 3. Авторизация

Лист `Справочник Web-пользователей` имеет заголовки в строке 4 и данные со строки 5:

`Логин | Пароль | ФИО | Контакт | Доступ`

Логин обрезается по краям, пароль сравнивается точно, а вход разрешён только при `Доступ = Да`.
Дубль непустого логина блокирует вход. Пароль и справочник не передаются в браузер.
Для истории actor равен `Контакт`, а при его отсутствии — `Логин`.

## 4. Бизнес-правила

- Ключ поиска: `ID объекта + ID типа документа`; в подсчёте участвуют активные, архивные и удалённые строки.
- `Один`: любая существующая строка с полным ключом блокирует второй документ.
- `Много`: фактическое имя — `<тип> №N`, где `N = число существующих строк + 1`. `ID типа документа` остаётся базовым.
- `ID документа` сохраняет формат `DOC-{ID объекта}-{NNNN}`.
- Все проверки, подсчёты, ID и записи повторяются на сервере внутри `withDocumentLock_()`.

## 5. Запись и история

Из объекта копируются договор, статус и даты объекта, ответственный прораб и его ID.
Автоматически заполняются даты создания/обновления/изменения статуса, actor,
`Источник создания = Web-приложение` и `Статус записи = Активная`. Остальные бизнес-поля пусты.
Успех создаёт одну логическую строку в «Истории изменений» и одну — в «Истории операций»,
связанные одним `ID операции`. Блокировка `Один` пишет операцию `Без изменений`.

## 6. Ручная публикация

1. Добавить/заменить файлы из раздела 2 в привязанном Apps Script проекте.
2. Убедиться, что лист Web-пользователей и все обязательные заголовки существуют.
3. Apps Script: **Deploy → New deployment → Web app**.
4. **Execute as:** владелец; **Who has access:** Anyone.
5. Нажать **Deploy**, авторизовать владельца и открыть выданный URL. Автоматический deployment не применяется.

## 7. Ручные приёмочные тесты

1. Войти корректными данными Ирины; проверить основной экран.
2. Ввести неверный пароль; вход запрещён.
3. Установить `Доступ = Нет`; вход запрещён.
4. Создать отсутствующий тип `Один`; проверить факт, ID, системные поля и обе истории.
5. Повторить пункт 4; кнопка заблокирована, дубль не создан.
6. Выбрать новый тип `Много`; проверить `№1`.
7. Создать ещё раз; проверить `№2` и оба документа в блоке.
8. Повторить с разными статусами из справочника.
9. Войти вторым пользователем; проверить actor в историях.
10. Быстро нажать создание дважды; ID и `№N` не дублируются.
