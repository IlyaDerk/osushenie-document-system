# Web-приложение создания документов

## Назначение и границы

`DocumentWebApp.html` — мобильный интерфейс для создания новых строк на листе
`Документы объектов`. Приложение не редактирует и не удаляет документы: эти
операции остаются в существующей карточке операциониста.

## Авторизация и сессия

Пользователи хранятся на листе `Справочник Web-пользователей`: заголовки в
строке 4, данные со строки 5. Обязательные заголовки: `Логин`, `Пароль`, `ФИО`,
`Контакт`, `Доступ`. Пароль хранится и сравнивается как точный текст только на
сервере. Вход разрешён при `Доступ = Да`; повторяющийся непустой логин блокирует
вход. Справочник и пароль браузеру не возвращаются.

После входа случайный token хранится в `sessionStorage`, а серверная сессия с
одним логином — в `PropertiesService.getScriptProperties()` без срока
истечения. Пароль в сессию не записывается. Кнопка «Выйти» удаляет серверную
сессию и клиентский token.

Каждый защищённый запрос заново читает справочник и разрешается, только если
пользователь существует, его логин уникален и `Доступ` по-прежнему точно равен
`Да`. Actor каждый раз формируется из актуального `Контакт`, а при пустом
контакте — из `Логин`. Удаление пользователя, дубль логина или отзыв доступа
немедленно удаляет серверную сессию. Даже после повторного включения доступа
старый token не восстанавливается: пользователь должен войти заново.

## Источники и правила создания

* Объекты читаются из `Объекты`; значение `Все` исключается. Сервер заново
  проверяет ID, дубль ID и обязательные объектные данные.
* Типы читаются из `Справочник документов` по ID. Допустимая повторяемость —
  только `Один` или `Много`.
* Статусы читаются из столбца `Статус документа` листа `Справочник для КО` и
  повторно проверяются перед записью.
* Ключ существования — `ID объекта + ID типа документа`, включая активные,
  архивные и удалённые строки.
* Для `Один` любая существующая строка блокирует создание, а `Номер
  документа` остаётся пустым.
* Для `Много` сервер берёт максимальный корректный положительный целый
  `Номер документа` и добавляет один. Пропуски не переиспользуются; при
  отсутствии корректных номеров нумерация начинается с 1.
* На переходный период учитывается legacy-суффикс `№N` строго в конце типа, но
  только если отдельное поле номера пусто. Заполненное отдельное поле имеет
  приоритет; числа из середины названия не извлекаются.

Сессия и актуальный доступ проверяются до входа в общую `withDocumentLock_()` и
повторно внутри неё. Только затем под блокировкой справочники и факты читаются
повторно, рассчитывается номер по `max + 1`, проверяется его свобода для пары объект/тип и
рассчитывается совместимый ID `DOC-{ID объекта}-{NNNN}`, после
чего одной пакетной записью создаётся строка. Если доступ отозван между двумя
проверками, факт и истории не записываются.

## Поля и история

Из объекта копируются название, договор, статус и даты работ, прораб и его ID.
Из типа берутся базовое имя, ID и повторяемость. `Тип документа` всегда хранит
точное каноническое имя, а назначенный сервером номер хранится отдельно в `Номер
документа`. В UI они объединяются только для показа (`КС-2 №3`); это отображаемое имя не
записывается в поле типа. Web App задаёт вручную только статус.
Автоматически заполняются даты создания/обновления/смены статуса, actor,
`Статус записи = Активная` и `Источник создания = Web-приложение`.

Поля документа, ЭДО, комментария, движения, оплаты, суммы, ГУ, сотрудников и
отчётного периода остаются пустыми. Успех создаёт одну строку факта, одну
логическую строку `История изменений` и одну строку `История операций` с общим
ID операции. Бизнес-блокировка `Один` пишет операцию `Без изменений`. Если факт
успел записаться, но история завершилась ошибкой, UI предупреждает о возможном
создании и не предлагает автоматический повтор.

## Ручная публикация

1. Добавить/обновить файлы проекта Apps Script: `SystemCore.gs`,
   `DocumentArchitectureCore.gs`, `CreateObjectDocuments.gs`, `WebAppAuth.gs`,
   `DocumentWebAppServer.gs`, `DocumentWebApp.html`. HTML
   остаётся `DocumentWebApp`, поэтому `doGet()` открывает его по прежнему имени.
   `DocumentArchitectureMigration.gs` для работы отдельного Web App не требуется.
2. Открыть редактор Apps Script из основной таблицы и один раз вручную выполнить
   `setupSystemSpreadsheetConnection()`. Функция сохранит ID активной таблицы в
   Script Property `SYSTEM_SPREADSHEET_ID`, не изменяя листы или их данные.
3. Проверить возвращённые название и ID таблицы. Без этой настройки Web App
   покажет инструкцию выполнить `setupSystemSpreadsheetConnection()`.
4. Не изменять `Code.gs` и существующие модули.
5. В редакторе Apps Script выбрать **Развернуть → Новое развертывание**.
6. Тип — **Веб-приложение**; выполнять от имени владельца проекта; доступ
   предоставить выбранной для MVP аудитории.
7. Нажать **Развернуть**, выдать требуемые разрешения и открыть полученный URL.
8. При последующих изменениях создавать новую версию развертывания вручную.

## Ручные приёмочные тесты

1. Войти корректными данными Ирины; затем проверить неправильный пароль и
   пользователя с `Доступ = Нет`.
2. Создать отсутствующий тип `Один`; проверить факт, ID, системные поля и обе
   истории. Повторный выбор должен показать документ и заблокировать кнопку.
3. Для нового типа `Много` проверить подсказку и создание `№1`, затем `№2`.
4. Повторить создание с разными статусами из справочника.
5. Войти вторым пользователем и проверить actor в факте и историях.
6. Быстро дважды нажать создание `Много`: ID и номера должны различаться.

## Первый тест пошагово

1. На листе пользователей убедиться, что у Ирины уникальный логин, правильный
   пароль и `Доступ = Да`.
2. Открыть URL опубликованного Web App на телефоне или в приватном окне.
3. Ввести логин Ирины и точный пароль, нажать «Войти».
4. Убедиться, что открыт экран «Создание документа», показано имя Ирины и
   доступны списки объекта, типа и статуса.
5. Нажать «Выйти» и убедиться, что снова показан экран входа.
