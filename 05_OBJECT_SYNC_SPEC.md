# Спецификация синхронизации данных объектов

## Назначение и запуск

Публичная функция `syncObjectDataToDocuments` массово переносит актуальные объектные
данные из листа `Объекты` в активные физические строки листа `Документы объектов`.
Она вручную назначается кнопке «Синхронизировать данные объектов»; `onOpen` и кнопки
программно не меняются. Один запуск создаёт одну операцию.

## Источник истины и поля

Единственный источник объектных данных — `Объекты`. Сопоставление выполняется по
`ID объекта`. Синхронизируются только:

- `Название объекта`;
- `Номер договора`;
- `Статус объекта`;
- `Ответственный прораб`;
- `ID ответственного прораба`.

Пустое значение источника очищает получателя. Равные значения не записываются и не
журналируются. При изменении объектного поля обновляются `Дата обновления` и
`Кто обновил (email)`; email журналируется только при фактическом отличии. Поле
`Дата изменения статуса документа` никогда не меняется из-за статуса объекта.

Три даты работ копируются из объекта только при создании документа. После создания
`Дата начала работ`, `Дата окончания (по плану)` и `Дата окончания (по факту)`
принадлежат документу, редактируются отдельно в карточке и намеренно исключены из
объектной синхронизации. Контрактная проверка запрещает случайно вернуть их в список.

## Даты и строки

Непустые даты должны быть настоящими объектами Date; сравнение выполняется по времени,
а не отображаемому тексту. Объект с некорректной датой или плановым окончанием раньше
начала полностью пропускается с причиной. Пустой `ID объекта` не обрабатывается.

Обновляются только строки со `Статус записи = Активная`. Архивные и удалённые строки
не читаются как кандидаты на изменение. Активная строка без ID документа или объекта
пропускается с предупреждением. При повторе ID объекта пропускаются все конфликтующие
источники с перечислением физических строк. При повторе ID документа обновляются все
подходящие активные физические строки и выдаётся предупреждение; дубль не исправляется.

## Блокировка и пакетная запись

Структура проверяется только для `OBJECTS`, `DOCUMENTS`, `CARD_DICTIONARY`,
`OPERATION_HISTORY`, `CHANGE_HISTORY`. Чтение, повторная проверка, резервирование ID и
все записи проходят под одной общей документной блокировкой. Заголовки и значения
берутся из `SYSTEM_HEADERS`, `H`, `SYSTEM_CONFIG`; буквенные/A1-адреса и `appendRow`
не используются. Запись группируется по разрешённым столбцам и соседним физическим
строкам через `setValues`; несинхронизируемые столбцы, включая формулы, повторно не
записываются.

## Истории и счётчики

Операция использует тип и источник `Синхронизация данных объектов`; изменение — действие
`Синхронизация` и источник `Лист объектов`. На каждое фактически изменённое поле, включая
`Дата обновления`, создаётся строка со старым/новым значениями, документом, объектом и
физической строкой. ID имеют форматы `OP-YYYYMMDD-NNNN` и
`CHG-YYYYMMDD-NNNN-MMMM`.

История операции содержит ноль загруженных в карточку документов, количество уникальных
ID документов с изменениями, физических строк, полей, дублей и ошибок. Комментарий
содержит объекты проверенные/корректные/пропущенные, активные строки, документы и строки
с изменениями, поля, причины и предупреждения. Статусы: `Успешно`,
`Успешно с предупреждениями`, `Без изменений`, `Ошибка`.

## Частичные сбои

Факты записываются до истории изменений. Если журналирование после этого падает,
факты не откатываются; операция по возможности получает `Ошибка`, а сообщение явно
говорит о записанных данных и неполной истории, сохраняя исходную техническую причину.
Критическая ошибка показывается экранированным HTML-диалогом.

## Справочник и административная защита

Синхронизация требует в `Справочник для КО` только значение `Активная` в системном
столбце. Обычные значения остаются свободно настраиваемыми. Необязательная идемпотентная
`setupSystemDictionaryGuards` добавляет двум системным ячейкам примечания, оформление и
собственную warning-only protection, не ограничивая редакторов и не защищая остальной
справочник. Существующие чужие защиты функция не изменяет и не ослабляет.

## Границы ответственности

Модуль не создаёт документы, не меняет документные/платёжные/операторские поля,
структуру листов, карточку, справочники клиентов/сотрудников/документов и не исправляет
дубли. Он не подключает внешние API и не выполняет merge или назначение кнопки.

## Уточнение по истории технических полей

При синхронизации бизнес-полей модуль обновляет в фактах «Дата обновления» и «Кто обновил (email)», но эти два технических поля не создают отдельные строки «История изменений». История уже содержит дату/время изменения и email пользователя, поэтому счётчик «Полей изменено» отражает только реально изменённые бизнес-поля объекта.
