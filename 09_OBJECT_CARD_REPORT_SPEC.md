# Карточка объектов

`ObjectCardReport.gs` владеет generated-листом `Карточка объектов` и полностью
пересобирает его публичной функцией `rebuildObjectCard()`. Исходные листы
`Объекты`, `Документы объектов` и `Справочник для КО` модуль только читает через
централизованные contracts `SystemCore.gs`; формулы не используются.

Snapshot включает все объекты. Ключ группировки — `ID объекта`, а отображаемое
имя берётся из канонического заголовка объекта `Название объекта` на листе
`Объекты`. Из документов учитываются только строки со `Статус записи = Активная`.

Статусные колонки следуют порядку справочника, дедуплицируются, затем дополняются
фактическими неизвестными статусами в natural order. Пустые статусы попадают в
последнюю колонку `Без статуса`. Global, object и orphan totals проверяются до
очистки отчёта: каждый активный документ должен быть назначен ровно один раз, а
total обязан равняться сумме status counts. Пустой или неизвестный `ID объекта`
попадает в отдельный orphan-блок.

Весь цикл `validate → read → model → publish` выполняется под одной системной
блокировкой, поэтому параллельный запуск не может опубликовать устаревший
snapshot поверх более нового. `Без статуса` канонизируется в одну последнюю
статусную колонку независимо от наличия значения в справочнике и фактах.

Под каждой непустой object/orphan summary находятся ровно шесть detail-полей и
collapsed row group; строка summary в группу не входит. Объект без документов не
получает пустую группу. Пересборка массово снимает прежнюю глубину групп и
удаляет содержимое только
generated-листа, записывает значения batch-операцией и не создаёт history facts.

После приёмки hourly time-driven trigger для `rebuildObjectCard` создаётся
вручную в Apps Script (**Triggers → Add Trigger**). Код не создаёт trigger
автоматически. Следующий отдельный функциональный блок — `Сводная руководителя`.
