# Архитектура документов v2: ручное обновление и миграция

## Важно

Код **не меняет физическую структуру** Google Sheets. До запуска новой
версии владелец вручную меняет два листа. Названия заголовков нужно
ввести буквально. Строки заголовков и начала данных не меняются.

## 2. Лист «Карточка операциониста»

В строке 5 разместить первые 27 заголовков из списка выше, затем:

28. `Статус записи`
29. `Номер строки в таблице фактов`

## 3. Порядок запуска

1. Сделать резервную копию таблицы.
2. Вручную изменить два листа по схеме выше. При вставке новых колонок не
   сдвигать значения относительно их заголовков.
3. Установить новую версию Apps Script.
4. Запустить `validateSystemStructure()`; все листы должны пройти проверку.
5. Один раз запустить `migrateDocumentsToArchitectureV2()`.
6. Повторно запустить проверку, затем перезагрузить Карточку операциониста.

Миграция берёт канонический `Тип документа` из `Справочник документов` по
`ID типа документа`. Суффикс после `№` переносится в пустой `Номер документа`.
Уже заполненный номер не перезаписывается. Каждое изменение пишется в историю.
Повторный запуск идемпотентен и вернёт нулевые счётчики.

## 4. Web App в переходный период

Web App хранит канонический тип и номер в разных полях. Для повторяемого типа
номер назначается сервером как `max + 1`; пропуски не заполняются. До завершения
миграции в расчёте также учитывается конечный legacy-суффикс `№N`, если новое поле
пусто. Предварительный показ номера не резервирует его: перед записью Web App повторно
читает факты, рассчитывает и проверяет номер внутри общей блокировки.

Имя вида `КС-2 №3` формируется только для отображения и не записывается обратно в
`Тип документа`.
