# Спецификация модуля создания документов по объектам

## Цель

Реализовать Apps Script-модуль, который по нажатию кнопки `Создать документы` массово проверяет все объекты и добавляет в `Документы объектов` только недостающие документы, предусмотренные `Справочник документов`.

Главная функция:

```javascript
createMissingDocumentsForAllObjects
```

Пользователь не выбирает строку объекта. Один запуск обрабатывает весь лист `Объекты`.

## 1. Отбор объектов

Скрипт читает все строки `Объекты`, начиная со строки 4.

Корректный объект должен иметь:

- `ID объекта`
- `Название`
- `Номер договора`
- `ID ответственного прораба`
- `Ответственный прораб`
- `Статус объекта`
- `Дата начала работ`
- `Дата окончания (по плану)`

Необязательны:

- `Адрес`
- `Дата окончания (по факту)`

Проверки:

- `ID объекта` не повторяется;
- даты начала и планового окончания являются настоящими датами;
- плановое окончание не раньше начала;
- полностью пустые строки игнорируются;
- некорректный объект пропускается, остальные обрабатываются;
- при дубле `ID объекта` пропускаются все строки с этим ID.

## 2. Правила создания

Скрипт читает `Справочник документов`, начиная со строки 5.

В комплект включаются только строки:

`Создавать при создании объекта = Автоматически`

Сравнение допускается без учёта регистра и лишних пробелов.

Обязательны:

- `ID типа документа`
- `Тип документа`

Весь запуск останавливается до записи, если:

- отсутствует ID или название у автоматического правила;
- один ID типа повторяется;
- одно название связано с разными ID;
- нет ни одного правила автоматического создания.

Поля `Обязательность`, `Срок на исполнение от даты создания` и `Повторяемость` пока не влияют на первоначальное создание.

Порядок создания совпадает с порядком строк справочника.

## 3. Проверка существования

Ключ:

`ID объекта + ID типа документа`

Документ считается существующим независимо от:

- `Статус документа`;
- `Статус записи`;
- `Источник создания`;
- заполненности остальных полей.

Создаются только отсутствующие сочетания.

Если сочетание уже продублировано:

- новый документ не создаётся;
- существующие строки не меняются;
- дубль отражается в предупреждениях.

Строка без `ID объекта` или `ID типа документа`:

- не участвует в сравнении;
- не блокирует создание;
- учитывается как предупреждение;
- автоматически не исправляется.

## 4. Поля новой строки

Автоматически заполняются:

| Поле | Источник / значение |
|---|---|
| `ID документа` | Формируется скриптом |
| `ID объекта` | `Объекты → ID объекта` |
| `Тип документа` | `Справочник документов → Тип документа` |
| `Номер договора` | `Объекты → Номер договора` |
| `Статус документа` | `Ожидает заполнения` |
| `Статус объекта` | `Объекты → Статус объекта` |
| `Дата начала работ` | `Объекты → Дата начала работ` |
| `Дата окончания (по плану)` | `Объекты → Дата окончания (по плану)` |
| `Дата окончания (по факту)` | Копируется, если заполнена |
| `Дата создания` | Текущая дата и время |
| `Дата обновления` | Равна дате создания |
| `ID типа документа` | `Справочник документов → ID типа документа` |
| `Кто обновил (email)` | Email запустившего пользователя |
| `Ответственный прораб` | `Объекты → Ответственный прораб` |
| `ID ответственного прораба` | `Объекты → ID ответственного прораба` |
| `Дата изменения статуса документа` | Текущая дата и время |
| `Источник создания` | `Создание документов по объекту` |
| `Статус записи` | `Активная` |

Остаются пустыми:

- `Дата документа`
- `Оригинал / ЭДО`
- `Комментарий`
- `У кого документ`
- `Где документ`
- `Кто передал`
- `Оплачен`
- `Сумма документа`
- `ГУ (Да/Нет)`
- `Условия ГУ`
- `ID сотрудника — у кого документ`
- `ID сотрудника — кто передал`
- `Отчётный период`

Записываются значения, не формулы. Новые строки добавляются в конец таблицы фактов.

## 5. ID документа

Формат:

`DOC-{ID объекта}-{порядковый номер}`

Примеры:

- `DOC-2605-0001`
- `DOC-2605-0002`
- `DOC-OBJ-0021-0001`

Правила:

- общая нумерация внутри объекта;
- максимальный существующий номер + 1;
- пропущенные номера не переиспользуются;
- глобальная уникальность проверяется перед записью;
- ID не меняется после создания;
- старые нестандартные ID не переписываются;
- создание выполняется под блокировкой.

## 6. Ошибки и предупреждения

Критические ошибки, останавливающие весь запуск:

- отсутствует лист;
- отсутствует или продублирован обязательный заголовок;
- нет корректных автоматических правил;
- ошибка или дубль в справочнике;
- отсутствует статус `Ожидает заполнения`;
- не получена блокировка;
- техническая ошибка чтения или записи.

Ошибки объекта — пропустить объект:

- отсутствует обязательное поле;
- некорректная дата;
- плановое окончание раньше начала;
- дублирующийся `ID объекта`.

Предупреждения — продолжить:

- дубли сочетания объект/тип;
- дубли `ID документа`;
- строки факта с неполным ключом.

## 7. Истории и результат

Создание выполняется под блокировкой из `SystemCore.gs`.

После успешной записи:

- одна строка — в `История операций`;
- изменения созданных документов — в `История изменений`;
- все записи связаны одним `ID операции`.

Статусы:

- `Успешно`
- `Успешно с предупреждениями`
- `Без изменений`
- `Ошибка`

Итог пользователю содержит:

- проверено объектов;
- корректных объектов;
- пропущено объектов;
- правил создания;
- документов уже существовало;
- документов создано;
- дублей объект/тип;
- дублей `ID документа`;
- строк с неполным ключом;
- время выполнения;
- причины пропусков и предупреждения.

## 8. Технические требования

- Использовать `SYSTEM_HEADERS`, `H`, `SYSTEM_CONFIG` и функции `SystemCore.gs`.
- В начале запускать проверку структуры.
- Не создавать второй независимый справочник заголовков.
- Искать столбцы только по заголовкам.
- Не использовать буквы столбцов.
- Читать и записывать массивами.
- Новые строки записывать пакетно через `setValues`.
- Не использовать `appendRow` в циклах.
- Не менять существующие документы.
- Не исправлять дубли автоматически.
- Не подключать внешние API.
- Не менять `onOpen`, карточку операциониста и существующую логику сохранения.
